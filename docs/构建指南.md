# 构建指南

## 1. 环境准备

| 组件 | 版本要求 | 备注 |
| --- | --- | --- |
| Windows | 10 1809+ / 11 x64 | |
| MSVC | VS 2022 Build Tools（v143） | 需勾选「使用 C++ 的桌面开发」 |
| Qt | ≥ 6.5（验证 6.8.3 msvc2022_64） | Quick、QuickControls2、Network、Svg、Concurrent |
| CMake | ≥ 3.21 | |
| Ninja | 任意近期版本 | |
| libsodium | 1.0.18+ | 需已编译的 `.lib` + `.dll` 与源码头文件 |
| FluentUI | 1.7.7 | 源码形式引入 |

## 2. 路径配置

`CMakeLists.txt` 支持三级覆盖，推荐用命令行传参：

```powershell
cmake -S . -B build\Release -G Ninja `
  -DCMAKE_BUILD_TYPE=Release `
  -DFLUENTUI_ROOT=D:/deps/FluentUI/src `
  -DLIBSODIUM_ROOT=D:/deps/libsodium/win64 `
  -DLIBSODIUM_SOURCE=D:/deps/libsodium-src
```

也可以设环境变量：`FLUENTUI_ROOT`、`LIBSODIUM_ROOT`、`LIBSODIUM_SOURCE`。

- `LIBSODIUM_ROOT` 下必须有 `libsodium.lib` 与 `libsodium.dll`
- `LIBSODIUM_SOURCE` 需包含 `src/libsodium/include`

## 3. 编译

```powershell
.\build.ps1                 # Debug
.\build.ps1 -Config Release # Release
```

脚本会自动载入 MSVC 环境（调用 `vcvars64.bat`）并运行 CMake 配置 + 构建。

> 脚本默认使用作者本机的 Qt / CMake / Ninja 路径，换机器时需要改三个变量：
> `$qtRoot`、`$cmakeBin`、`$vcvars`。

## 6. 已知环境坑

### 6.1 构建被中断后必须清理

增量构建如果被 Ctrl+C 打断，可能留下**被截断的目标文件**（时间戳新于源码），后续增量构建会复用它，产生能编译成功但一启动就 `0xC0000005` 的坏二进制。

处理：删掉 `build\Release` 后全量重建。

### 6.2 无边框窗口最小化失效（已修）

FluentUI 1.7.7 的 `FluFrameless` 在 Windows 上用 `Qt::CustomizeWindowHint` 清空默认样式位后，只补回 `WS_MAXIMIZEBOX | WS_THICKFRAME | WS_CAPTION`，漏掉 `WS_MINIMIZEBOX`。Windows 会**静默忽略**没有该位的窗口的最小化请求。

若你使用未经修补的上游 FluentUI，症状是：点最小化没反应，画面闪一帧暗色。补法：

```cpp
// src/FluFrameless.cpp，两个分支都补上 WS_MINIMIZEBOX
::SetWindowLongPtr(hwnd, GWL_STYLE, style | WS_MINIMIZEBOX | WS_MAXIMIZEBOX | WS_THICKFRAME | WS_CAPTION);
```

### 6.3 中文路径与 QML 扫描

Qt 的 `qmlimportscanner` 在非 UTF-8 代码页下处理含中文的路径会乱码。本项目在 `build.ps1` 里通过 ASCII 联接目录（junction）绕开；其他项目可直接把工程放在纯 ASCII 路径下。
