# 功能说明：图片处理、载体放置与链接生成

本文说明一次完整传输在本地与平台上分别发生了什么。

## 一、概述

「文件取件」不直接上传你的原文。它把内容加密、装箱，然后**附加到一张图片的尾部**，再上传这张图片。平台上看到的就是一张图，取件方凭 5 位口令码定位它。

## 二、本地处理链路

### 1. 读取与压缩

- 任意文件按原样读取；图片类（jpg/png/webp/bmp 等）可开启压缩，统一转 WebP（质量 75）
- **只有压缩后更小才采用**，否则保留原图，避免越压越大
- 文本内容直接作为字节流处理，不做字符集转换

### 2. 加密

- 使用 libsodium 的 `crypto_secretstream_xchacha20poly1305`（流式 AEAD）
- 每次制作生成新的随机密钥，随容器头部一起封装
- 分片加密时每片独立带认证标签，任何篡改都会在解密阶段被拒绝

### 3. 装箱（TMSHARE1 容器）

容器由头部 + 分片组成：

- 头部记录：协议版本、分片数、单片大小、原始文件名、原始大小、压缩标记、密钥与流头
- 分片按顺序排列，每片带索引与校验信息
- 大文件自动分片（受平台单文件大小限制），提取时按索引重组

### 4. 生成载体图片

关键点：**数据附加在图片字节流的尾部**，不改动图片本身的像素数据。

- 因此图片在任何看图工具里都能正常打开
- 生成的载体在写盘前会**回读校验**：重新解析尾部数据并试解密一次，确认可恢复才算成功
- 对会被 CDN 重新编码的平台，使用固定规格的承载图，保证尾部数据原样保留

## 三、上传与链接生成

### 平台侧

| 平台 | 上传方式 | 返回 |
| --- | --- | --- |
| 小飞机网盘 | 直连接口（`scripts/feejii.py`） | 文件直链 |
| QQ 频道 | 频道附件/图文接口 | 频道消息 |
| 哔哩哔哩 | 动态图片（固定承载图） | 动态链接 |

### 后端登记

上传成功后，客户端把「链接 + 元数据」提交到后端，后端返回一个 **5 位字母口令码**：

```json
{
  "action": "register",
  "protocol": 1,
  "urls": ["https://..."],
  "fileName": "example.zip",
  "fileSize": 1234567,
  "parts": 1
}
```

- 同一个链接可重复登记（口令码永久有效）
- 口令码只索引链接与元数据，不含任何明文内容

## 四、取件链路

1. 输入 5 位口令码 → 查询后端，得到载体链接列表
2. 下载载体图片（或分片图片）
3. 解析图片尾部 → 还原容器 → 按索引合并分片
4. 解密 → 解压（若为压缩包）→ 写入目标目录
5. 输出文件名与大小，失败时明确报错（口令不存在 / 载体损坏 / 校验失败）

## 五、失败与边界

| 情况 | 表现 |
| --- | --- |
| 口令码不存在 | 提示码无效 |
| 平台对图片重编码 | 尾部数据损坏，解析失败（换平台或改用固定承载图） |
| 分片缺失 | 提示缺少第 N 片 |
| 密文被篡改 | 解密认证失败，拒绝输出 |
| 磁盘空间不足 | 写入前检查并提示 |
